Protocol command (workspace SDK): `local/tools/dotnet/dotnet.exe run --project mod/tests/ProtocolTests -c Release`.

Do not equate protocol tests with in-engine tests: runtime command adapter currently implements stricter observed-revision rejection independently of the tested general sequencer.

Required next gameplay cases: blueprint placement/deletion; research purchase and operator goals; constant signal edit; disconnect during snapshot; snapshot recovery; long-session bounded throughput and stable memory on a large factory. Unity reports GraphicsBuffer/JobTempAlloc cleanup warnings during QA shutdown; their origin and performance impact are not yet isolated.

Build QA with `mod/tools/build-qa.ps1 -GameDirectory '<installed-game>'`, prepare the host/client profiles with `mod/tools/prepare-qa.ps1` (also `-ProfileName client-profile`), then run `mod/tools/run-qa.ps1 -PeerCount 3` for four processes. The runner prepares observer profiles, validates every participant and shuts down only processes it created.

QA copies live only in ignored `local/qa`. GameProbe inventories persistent-path calls and patches **only copies under local/qa** to redirect `Application.persistentDataPath`, disable managed PlayerPrefs and use the game's StartInMainMenu mode. It removes the copied boot.config single-instance setting. `SHAPEZ2_COOP_QA_PROFILE` selects a separate profile per process; it must be inside `local/qa`. Original game DLLs are read-only. The QA bot is excluded from distribution. A successful scorer must require explicit results in both client logs, matching session/step evidence, no faults, and clean exits; a timeout/missing result is never PASS.

QA also skips the two cosmetic DLC catalogue builders. Their asynchronous menu tasks otherwise access disposed views during automated joins. This adjustment is compiled only with `CoopQa=true`; it does not suppress gameplay exceptions, alter the factory or establish normal-build DLC/UI compatibility.

Frequency/prediction commands: `mod/tools/run-qa.ps1 -PeerCount 2 -SimulationHz 20` (also 30 and 60); `-SimulationHz 20 -SwitchRates` exercises live 20→30→60 changes. The bot holds clients for at least 12 simulated seconds after reconnect; scorer requires matching ordered partition digests after the final snapshot. QA adds 200 ms outbound intent delay to exercise visible pending records before replies. It is excluded from the normal build and is not a WAN/loss/jitter test. Prediction rendering assertions verify the native draw call and absence of simulation changes; ghost pixel appearance is unverified. Deletion prediction is a red pending-removal overlay, not removal from the replica map. Platform/blueprint preview coverage remains unverified; large-world performance measurements are recorded above. No synchronization checks are disabled at 60 Hz.

UI command after `build-qa.ps1`: `mod/tools/run-ui-qa.ps1`. It uses a separate executable/profile and read-only junctions to the isolated game data, leaves manual windows alone, waits for the native menu transition, runs in the background and tests real HUD callbacks. No networking/Steam account is used. Screenshots need a rendering process without batchmode; a black initial capture is not visual evidence. Earlier startup/Steam/shutdown-interrupted runs were not passes. The normal alpha.2 compiles without this UI bot or screenshot module reference. Authoritative command processing and simulation stepping were not changed by these UI fixes; the full multiplayer gate was not repeated for alpha.2.

Next priority: extend the existing two-client gameplay gate to blueprint/platform placement and research progression with real production, then extend the proven corruption check to additional production systems. Keep the current frequency/prediction/reconnect gates as regressions.

## Large-factory repair (alpha.3)

The original four-backup save directory was copied to an ignored fixture and verified by SHA256. Every runner uses a further private input copy and fresh profiles. The reproduced world has 289,840 buildings and 1,374 islands. The original game assemblies and save files are unchanged.

- Root causes: synchronous ENet service stopped during roughly 10-second native world loading; full-world hash every five simulated seconds created long pauses and garbage; simulation forced zero native workers; cargo dictionary iteration produced different snapshot hashes despite equal per-building state. Partial-client cleanup unregistered handlers that had never been attached. Concurrent menu loads leaked rendering objects and triggered a Unity finalizer crash.
- `perf-smooth-20261021-191454` passed, two exits 0: native 435.6 frame/s, host-alone 422.9, native-after 418.2. Host-alone p95 5.54 ms, maximum 23.19 ms, 300 steps / 15 simulated seconds, no measured GC collections. Connected host p95 11.48 ms, p99 13.63 ms, maximum 31.12 ms; partition hashes averaged 6.02 ms. Compare the failed baseline above (179.9 host frame/s, p95 26.82 ms, maximum 1459.52 ms). These are controlled uncapped engine frame-throughput measurements, not a prediction of visible FPS at arbitrary settings. Connected-before comparison is unavailable because the old client could not join.
- `perf-after-canonical-20261021-191206` and `perf-reliable-edits-20261021-192248` passed with host eight / client three workers. The latter includes background ZIP packaging, four committed build/delete/replacement edits, rejected stale deletion and reconnect retaining revision 4. Full loaded-world snapshots and subsequent actual-state partition checks matched; both processes exited 0 without exceptions.
- `perf-hz60-stall-desync-20261021-192916` passed the explicit negative gate: 60 Hz selected, render cap 60, injected five-second client-main-thread stall, subsequent full partition coverage, then clearing a real producer output immediately before its partition check. The replica stopped on Production state checksum mismatch; host stayed active; both exited 0. This fixture adds one isolated QA producer because no occupied conveyor was found in the supplied factory. Counts stayed 289,841 during corruption: detection covers dynamic production, not just topology. The expected checksum exception is accepted only with explicit corruption/isolation markers; unrelated exceptions still fail the gate. This does not prove sustained real-time 60 Hz under that workload.

`run-perf-qa.ps1 -SaveFile '<copy under local/qa>' -Label comparison` measures native/host/native, joins two real game processes and requires all 256 partition indices to match. Set `SHAPEZ2_COOP_PERF_EXERCISE=1` to add build/delete/stale/reconnect. QA-only worker-count variables select different engine worker counts. `-ExpectDesync` injects the producer-buffer corruption; `SHAPEZ2_COOP_PERF_STALL_MS=5000` adds a bounded client stall. Do not compare deliberately stalled samples to ordinary performance samples.

Full capture and loaded-world verification remain synchronous and expensive at join boundaries. ZIP packing alone runs in a bounded pure-data worker. Full preview-purity hashes are disabled only inside the large performance harness; the dedicated small-factory regression retains them. Early repair attempts that exposed cargo-order mismatch, duplicate menu loading, or an artificial full-preview-hash backlog were failed runs, not passes. Native GraphicsBuffer/JobTempAlloc shutdown warnings remain; successful gates require exit 0 and no unexpected exceptions.
